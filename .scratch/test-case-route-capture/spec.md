# 保存用例复用成功路线与断言核查

用户已确认：保存成功任务为用例时关联原任务的安全路线；修复硬断言验证链路；展示已保存、待验证、可回放状态。

- 保存用例必须由用户确认，技能原有学习门槛保持不变。
- 保存原运行 ID。后台结果判断和用户保存可以任意先后，关联请求落盘，按精确用例版本关联。
- 只有通过 Mika LearnGate、RouteRecorder 的运行才成为来源；部分完成、未知、付款接管、保护页面等不能获得快路径。
- 从原目标录制参数槽，再添加用例执行目标后缀；避免新增文字步骤重复参数导致槽提取失败。原路线保留，生成专属用例路线。
- 本地绑定命中后跳过路线选择模型。现有界面校验、操作确认和失败回退保留；不承诺零模型调用。
- MP 的断言核查在任务仍持有屏幕时运行；Mika 普通任务不新增核查。
- HARD 支持可选 `expectedText`，代码对当前目标页面进行完整文字匹配，保留数字边界。模型结果不能覆盖 HARD 失败。描述型旧断言仍可导入，但缺少客观校验配置时为待验证。
- SOFT 复用 Mika Verifier；全部必需断言通过才允许绑定。按断言 ID、类型、用例版本和最新完整核查事件判定，不能拼接不同核查的成功项。
- 页面不可读、保护页面、网络核查失败只标待验证，不重放交易。
- 核查结果和可获取的截图进入 RunStore 与报告；HTML/ZIP/PDF 使用核查失败信息和截图。
- 用例库显示已保存／待验证／可回放。可回放表示已有可用路线，执行时仍需重新校验。
- 新增能力放在 MP 自有文件，TaskRun 保留少量调用挂点，保留上游同步和 CI 保护。

硬断言 YAML 示例：

```yaml
assertions:
  - id: paid
    kind: hard
    description: 订单状态正确
    expectedText: "订单状态：支付成功"
    required: true
```

文字匹配只能证明页面展示事实；后端交易真实性、金额归属等需要各自专用证据适配器，不能从一个成功提示推断。

验收覆盖保存与后台判定的两种时序、参数槽、版本隔离、禁用来源、硬断言失败不能被软断言覆盖、报告截图、JSON/YAML 兼容与本地选路零模型调用。
